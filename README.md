# Akarsh Interiors — Website

Multi-page website for Akarsh Interiors (Anantapur · Kurnool · Nandyal), built with Next.js 16 (App Router), React 19, TypeScript, Tailwind CSS 4, Framer Motion, React Hook Form + Zod and Radix UI.

> **Status:** complete and building cleanly. All imagery comes from Akarsh Interiors' own files: the official logo,
> 19 design projects built from the 3D presentation PDFs, 3D/2D drawing pairs, and 11 walkthrough videos.
> Projects are labelled "3D Design" and have no city/size until those details are confirmed — see "Before launch".

## Getting started

Requires **Node 20.9+**.

```bash
npm install
cp .env.example .env.local
npm run dev        # http://localhost:3000
npm run build && npm start   # production build
```

## Before launch

1. **Project details** — for each project, confirm city, size and whether it has been executed, then add them in the
   `overrides` object in `src/data/projects.ts` (e.g. `"i7-villa": { city: "kurnool", areaSqFt: 3200, stage: "completed" }`).
   City pages show a project once it has that city. Project titles were written to avoid client names — rename freely.
2. **Videos** — if a walkthrough video belongs to a project, set `projectSlug` in `src/data/videos.ts`.
3. **Brands** — the 13 categories in `src/data/brands.ts` marked `source: "akarsh"` are the client's own list (incl.
   Laminates: Skydecor, Dorby, Advance; Glass: Saint-Gobain, Modiguard; Adhesives: Fevicol, Jivanjor, Araldite). The 3
   categories marked `source: "suggested"` (Kitchen Sinks & Appliances, Bath Fittings, Tiles) were added during the build —
   keep the ones you use, delete the rest, or set `SHOW_SUGGESTED_BRANDS = false`. Confirm ProBond's manufacturer/website
   and add an Anchor logo if wanted (both show as name cards for now).
4. **Photos of completed work** — when available, add them as new projects (see below); they can sit alongside the 3D designs.
5. **Facts to confirm** — free site visit / quotation / 3D design conditions (FAQ text in `content.ts` and `/terms`), kitchen accessory list, privacy policy and terms wording.
6. **Optional** — email, office address (enables the map + address in structured data) and social links in `src/lib/site.ts`; team members in `src/app/about/page.tsx`; city photos via `coverImage` in `locations.ts`.
7. Set `NEXT_PUBLIC_SITE_URL` to the live domain.

Renders showing third-party logos (e.g. a Netflix logo on a TV) or film stills were deliberately left out, as were floor plans and bathrooms.

### Adding more 3D presentation PDFs
Extract the page images into a folder per PDF (pypdf), add an entry to the `P` list in `scripts/build-design-projects.py`
(choose pages and tag each with a room), then run `python3 scripts/build-design-projects.py <extracted-dir>`.

## Adding a project

1. Create `public/assets/projects/<project-slug>/` and add photos (JPG/WebP, ~2000px wide is plenty — Next.js generates responsive sizes).
   Videos go in `public/assets/videos/` (MP4, H.264, ideally under 20 MB) with a poster image.
2. Add an entry to `src/data/projects.ts`:

```ts
{
  id: "p7",
  slug: "3-bhk-sai-nagar-anantapur",
  title: "3 BHK Apartment",
  city: "anantapur",                 // must match a slug in locations.ts
  propertyType: "3 BHK",
  category: "Complete Home Interiors",
  description: "Short, factual summary of the project.",
  coverImage: "/assets/projects/3-bhk-sai-nagar-anantapur/living-1.jpg",
  gallery: [
    { id: "p7-1", type: "image", url: "/assets/projects/3-bhk-sai-nagar-anantapur/living-1.jpg",
      altText: "Living room with TV unit and cove lighting", room: "living-room", sortOrder: 0 },
    // ...
  ],
  videos: [
    { id: "p7-v1", type: "video", url: "/assets/videos/3-bhk-sai-nagar.mp4",
      thumbnail: "/assets/projects/3-bhk-sai-nagar-anantapur/living-1.jpg",
      altText: "Walkthrough of the 3 BHK apartment", room: "other", sortOrder: 0 },
  ],
  rooms: ["living-room", "kitchen", "bedroom"],
  materials: [],                     // only documented materials/brands
  services: ["complete-home-interiors", "modular-kitchens"],
  featured: true,                    // shows on the home page (first 4)
  published: true,
  // areaSqFt, style, completionDate, challenges, solutions, beforeAfter — only if verified
}
```

Room keys: `living-room`, `bedroom`, `kitchen`, `dining`, `wardrobe`, `tv-unit`, `pooja`, `other`.
The project gets its own page, appears in filters, city pages, related projects and the sitemap automatically.

## Connecting the enquiry form

All forms validate on the client (Zod) and include a honeypot spam trap and consent checkbox.

- **No backend (default):** the submit button reads "… via WhatsApp" and opens WhatsApp (+91 96663 06868) with the enquiry pre-filled. Nothing is stored on the site.
- **With a backend:** set `ENQUIRY_WEBHOOK_URL`. Forms then POST to `/api/enquiry`, which re-validates server-side, rate-limits, and forwards the enquiry JSON
  (`id, name, phone, email, city, service, propertyType, area, budget, timeline, message, sourcePage, createdAt, status`) to the webhook,
  then redirects to `/thank-you`. Works with Google Apps Script (→ Google Sheets), Zapier, Make, n8n or a CRM webhook.
  Optional `ENQUIRY_WEBHOOK_SECRET` is sent as a Bearer token.

The in-memory rate limiter is per server instance; on serverless hosting use the provider's firewall/rate limiting for stronger protection.

## Service-area map

`src/components/map/ServiceAreaMap.tsx` draws Andhra Pradesh from real boundary data (no API key, no third-party tracking).
The SVG paths live in `src/data/ap-map.ts`, generated by `scripts/build-ap-map.py` from geoBoundaries
(DataMeet / ECI, CC BY 2.5 IN; districts ODbL — the attribution line under each map is required). The service area is all of Andhra
Pradesh plus greater Hyderabad (tinted on the map); 10 cities have their own page and pin, and `TOWNS` adds smaller
towns as dots. To add a city page, add its coordinates to `CITIES` in the script, re-run it, and add the city (with a
`region`) to `src/data/locations.ts`. Short wording for the service area lives in `SERVICE_AREA` in that file.
City card photos come from Wikimedia Commons; their credits are stored with each city and shown on the card (required by CC BY-SA).

## Brand logos

Logos in `public/assets/brands/*.webp` are the brands' own artwork, taken from each official website (a few global
brands from Wikimedia Commons), trimmed and saved at 200px height. They're shown only to identify the brands used, with a
"trademarks of their respective owners, no partnership implied" note. To add a brand: drop `<id>.webp` in that folder,
add an entry to `brandDirectory` with `logo: L("<id>.webp")` (`darkLogo: true` for white artwork), and list its id in a
category's `brands` (and `preferred` to highlight it).

## Laminate & tile library (Materials page, `#library`)

The "Browse Materials" section on `/materials` (the old `/materials/finishes` URL redirects there) lists only laminates
and tiles taken from the client's PDF design presentations — nothing is invented and no third-party product photos are
used. Each entry in `src/data/finishes.ts` has a close-up (`public/assets/finishes/*.webp`, tiles prefixed `tile-`) cut
from that PDF's render; `seenIn` links to the project page built from the same PDF. All / Laminates / Tiles tabs, filters
(Product, Decor Family, Finish), search, sort, detail panel and a WhatsApp shortlist. The temple-elephant pooja door and
elephant Pichwai are `pinned` to the top.

**Dorby fluted laminates** (`src/data/dorby.ts`, 41 shades): names, shade codes and flute profiles (BF Bamboo Flute,
FF-L/FF-R diagonal, SC sectioned) from Dorby's public fluted-laminate collection, each linking to its
official product page. Dorby's product photos are not used — `FluteBoard` draws each sheet from the shade's colour and
profile. No prices are shown (re-pull the list from
`https://www.dorbypanels.com/collections/fluted-laminate/products.json` to refresh shades). If you hold dealer permission to use Dorby's
images, add `image` to an entry and the photo replaces the drawing.

## Content audit

`node scripts/audit-content.mjs` checks that every source PDF is accounted for, every referenced image/video exists,
there are no duplicate images, project rooms/services are consistent, and every brand logo/brand id resolves. Run it after adding content.

## Moving to a CMS later

Pages read content only through the functions in `src/data/*` (`getProjects`, `getProject`, `getLocations`, …) typed by `src/lib/types.ts`.
To use Sanity, Payload or Supabase, re-implement those functions to fetch from the CMS — the pages don't need to change.

## Deployment

Any Node host that supports Next.js 16 (Vercel recommended). Set the environment variables from `.env.example`, then `npm run build`.

**Vercel**

1. Push this repo to GitHub, then in Vercel choose **Add New → Project** and import it. The framework (Next.js), build command and output are detected automatically; Node 20+ is required (`engines` in `package.json`).
2. In **Settings → Environment Variables** add:
   - `NEXT_PUBLIC_SITE_URL` — the live address, e.g. `https://akarshinteriors.com` (or the `*.vercel.app` URL until the domain is connected). Used for canonical URLs, the sitemap and Google business data.
   - `ENQUIRY_WEBHOOK_URL` / `ENQUIRY_WEBHOOK_SECRET` — optional. Without them the enquiry forms open WhatsApp with the details filled in.
3. Deploy. To use the real domain, add it under **Settings → Domains**, update `NEXT_PUBLIC_SITE_URL`, and redeploy (`NEXT_PUBLIC_*` values are baked in at build time).

`source-assets/` (the original PDFs and video) is git-ignored and never deployed — only the web copies in `public/assets` are.
